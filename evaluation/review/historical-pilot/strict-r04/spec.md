## Findings

### SPEC_R04_01：多次初始化且末轮不是最优时，恢复最优参数前计算标签，导致返回标签不属于最终模型

- id：`SPEC_R04_01`
- title：多次初始化且末轮不是最优时，恢复最优参数前计算标签，导致返回标签不属于最终模型
- file：`r04/sklearn/mixture/base.py`
- line：263
- severity：P1
- 契约：第 197—202 行承诺保留最大似然或下界的模型，再预测输入标签；第 260—262 行明确要求 `fit_predict(X)` 与 `fit(X).predict(X)` 一致。
- 触发：`n_init > 1`，较早一次初始化得到最高下界，最后一次初始化得到不同的分类结果且下界更低。
- 根因：第 255—258 行只保存最优参数，迭代结束时对象仍持有末轮参数；第 263 行先用末轮参数计算 `log_resp`，第 272 行才恢复 `best_params`，第 276 行仍返回先前的标签。
- 具体证据：假设两次初始化的最终下界分别为 −1 和 −2，且同一输入点在两轮的最大责任度分量分别为 0 和 1，则保存第一轮参数，但返回该点的标签 1。调用结束后的 `predict(X)` 在第 374 行使用第一轮参数，得到标签 0。该见证是对允许的初始化结果进行静态控制流推导，不是执行结果。
- 影响：调用者得到的训练标签与对象实际保存的分量编号或分区不一致，不能可靠地将标签与模型参数对应。
- 最小修复方向：将最终 E-step 放到 `_set_parameters(best_params)` 之后，再返回标签。

### SPEC_R04_02：首次启用 warm_start 时仍采用 n_init，违反只初始化一次的接口承诺

- id：`SPEC_R04_02`
- title：首次启用 warm_start 时仍采用 n_init，违反只初始化一次的接口承诺
- file：`r04/sklearn/mixture/base.py`
- line：222
- severity：P2
- 契约：第 177—179 行明确声明 `warm_start=True` 时忽略 `n_init`，首次调用只进行一次初始化，后续调用延续训练。
- 触发：新建模型，设置 `warm_start=True`、`n_init=2`，首次调用 `fit(X)`。
- 根因：第 191 行进入 `fit_predict`；对象尚无 `converged_`，因此第 221 行得到 `do_init=True`，第 222 行选用 `self.n_init`，而非根据 `warm_start` 强制单次初始化。
- 具体证据：第 230 行执行两轮循环，每轮都经第 233—234 行调用 `_initialize_parameters`；第 255—258 行随后在两轮之间挑选参数。即使 `warm_start=True`，首次运行仍执行多起点择优。
- 影响：`n_init` 没有按文档被忽略，首次训练的参数选择及随机数状态推进可能不同于承诺的单次初始化。此项报告的是正常路径语义，而不是单纯性能代价。
- 最小修复方向：当 `warm_start=True` 时将实际初始化次数设为 1，同时保留首次需要初始化、后续复用参数的逻辑。
