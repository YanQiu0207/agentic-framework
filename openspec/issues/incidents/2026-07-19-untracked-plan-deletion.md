# 未跟踪方案文档误删事故复盘

**日期**：2026-07-19

**级别**：严重流程事故

**状态**：已恢复，预防规则已持久化

## 1. 事故摘要

主 Agent 将未跟踪文件 `docs/design-docs/framework/dual-track-merge/spec.md` 判断为重复方案，并使用 PowerShell `Remove-Item` 直接删除。该命令没有进入 Windows 回收站，Git 也无法恢复未跟踪文件。

用户发现文件不在回收站后指出：该文件由当前会话写入，应优先从会话历史恢复，而不是直接清理或凭残片重写。

## 2. 影响

- 原始文件一度不可见，造成方案证据链中断。
- 花费额外时间搜索 Codex 与 Claude Code 会话记录。
- 更严重的影响是破坏了用户对 Agent 文件操作边界的信任。

最终从 `~/.claude/projects/` 下的会话 JSONL 中找到原始 `Write` 工具载荷，按原文恢复出 10,145 字节、150 行文件。恢复后保留该方案，并将其标记为 `Superseded`，没有再次删除。

## 3. 根因

### 3.1 直接原因

- 把「未跟踪」错误理解为「可丢弃」。
- 未核对创建者、用途、内容差异和恢复路径，就把文件定性为重复。
- 使用永久删除命令，没有先移动到隔离区或建立备份。

### 3.2 流程根因

- 缺少删除前检查表：Git 状态、来源、用户价值、恢复证据、删除授权。
- 主 Agent 没有把其他 Agent 或其他会话生成的文件视为需要裁决的正式产物。
- 在两份方案尚未完成比较前，提前执行了不可逆清理。

## 4. 正确处理方式

遇到疑似重复或废弃文件时，应按以下顺序处理：

1. 使用 `git status --short` 判断文件是 tracked、untracked 还是 ignored。
2. 核对文件来源、创建会话、大小、哈希和内容差异。
3. 在替代方案完成比较并获得结论前，保留两份文件。
4. 优先通过状态字段、重命名或 `Superseded` 标记表达废弃。
5. 必须移除时：tracked 文件使用 Git 保留可恢复记录；untracked 文件先复制到明确的恢复位置，并取得用户明确授权。
6. 禁止用 `Remove-Item`、`rm` 等永久删除命令清理来源不明或尚未裁决的任务产物。

## 5. 本次纠正动作

- 从 Claude Code 会话历史完整恢复原文件。
- 保留两份方案，新增逐维度对比并明确最终裁决。
- 旧 Tooling 仓库采用非破坏性退役：只增加迁移提示，不物理删除历史实现。
- 安装器删除操作只接受经过 Schema、路径白名单和哈希验证的 Manifest，并提供事务回滚测试。

## 6. 已持久化规则

已在全局 Agent 规则 `~/.codex/AGENTS.md` 中增加：

该规则经用户明确确认后写入，覆盖删除前检查、非破坏性废弃和会话历史恢复三个环节。
