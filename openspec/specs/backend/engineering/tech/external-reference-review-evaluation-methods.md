# Review 效果评测：外部方法与适配建议

**核验日期**：2026-10-25。

**状态**：已读取论文方法与公开规则，未复现其排行榜；以下建议不代表已完成 strict 补测或实现新的评分分类。

## 结论

优先借鉴 SWR-Bench 的 PR 级正负例设计、多次 Review 聚合对照，以及 SWE-PRBench 的清单外发现分类、上下文消融和裁判校准。不能直接把 SWE-bench 的修复任务成功率当作 Review 效果，也不能因 reviewer 更多就推断技能有效。

## SWR-Bench

来源：[论文 v1](https://arxiv.org/html/2509.01494v1)，重点为数据构建、评估方法与多 Review 聚合实验。

论文报告最终包含 500 个 Change-PR 和 500 个 Clean-PR，结合代码变更与完整仓库上下文；标注关联审查意见与后续代码修改，人工验证阶段每个 PR 至少由两人独立标注。评估采用具体问题的语义匹配，并研究多 Review 来源经分析、过滤后的聚合效果。

建议借鉴：

- 使用真实 PR diff 和可访问上下文，不仅审查挑选出的旧模块。
- 纳入核验过的负例；修复后版本只代表目标缺陷被移除，不代表整个文件无其他问题。
- 增加「普通审查重复多次再聚合」对照，区分专业分工收益与增加计算次数的收益。
- 分开统计目标召回、误报、功能问题和流程完成度。

**不照搬**：论文将未匹配任何 ground truth 的预测计为 FP，这依赖清单充分，不能直接套用于本项目出现的清单外发现。论文报告的聚合增益不代表本框架的预期收益。

## SWE-PRBench

来源：[论文 v1](https://arxiv.org/html/2603.26130v1)、[v0.4.1 公开规则](https://github.com/FoundryHQ-AI/swe-prbench/blob/379f0bfd8978a1734cd8399e115d04d4fdceeb89/RUBRIC.md)、[评测仓库](https://github.com/FoundryHQ-AI/swe-prbench/tree/379f0bfd8978a1734cd8399e115d04d4fdceeb89)。

| 分类 | 原规则含义 | 本项目用途 |
| --- | --- | --- |
| CONFIRMED | 与人工评论的底层问题、功能区域及所需改动类型一致 | 匹配冻结目标，防止仅位置相近就给分 |
| PLAUSIBLE | 依据可见代码、观察正确且合理，但人工清单没有此项 | 清单外发现单列，不自动当作幻觉或已证实缺陷 |
| FABRICATED | 事实错误、编造符号或不存在的缺陷等 | 需给反证才能判为错误发现 |

本项目还应保留「证据不足／待裁定」；不能因无法证明成立就自动判为 FABRICATED。引用上下文外行为时，应区分确实编造与材料不足。

论文还采用一对一匹配防重复计分、diff／文件／更完整上下文消融、跨裁判核验及盲评一致性检查。可以借鉴方法，但本次没有独立复现其数值。上下文效果只代表其特定构造，不推广为「上下文越少越好」。

**不照搬**：综合分权重、embedding 阈值和解析失败扣分属于任务特定选择。本项目优先展示分项、失败原因和裁定覆盖率，不用任意权重拼总分。

## strict 补测设计

先补跑原 4 个案例的 strict 组，保持已有普通组与 standard 组证据不变；这仍是探索性小样本，不宣称统计显著。后续扩展 PR 级数据时预注册：

| 组 | 执行方式 | 回答的问题 |
| --- | --- | --- |
| A | 普通单次 Review | 基线能力 |
| B | 普通 Review 多次执行并聚合，记录总调用量和用量 | 增加计算本身的收益 |
| C | strict 的 5 位 reviewer 原始候选，语义去重后独立评估 | 分工是否增加有效候选 |
| D | 同次 strict 的 Critic 与独立 Judge 最终输出 | 是否减少误报，是否误删正确发现 |

C 与 D 是同一执行链的中间与最终产物，不是独立抽样。B 与 D 若无法匹配实际 token／费用，只能称调用规模近似对照，不能宣称等预算。未执行 Critic／Judge、超时和解析失败单列，不把 reviewer 候选冒充 strict 最终结果。

## 评分与证据约束

1. 固定目标召回；额外发现单独评估，不事后扩大目标清单美化结果。
2. 报告错误发现、有效清单外发现、待定发现及各指标的裁定覆盖率。
3. 保留 strict 逐条保留／丢弃记录，检查错误过滤，不只看最终条数。
4. 冻结模型、源码、技能、提示词与规则；预先规定重复次数，按任务配对，不挑最好结果。
5. 隐藏分组后裁定，并以人工抽检校准 AI 裁判；未校准时只称 AI 初评。
6. 报告实际调用数、可观测 token、时间和费用；未知费用为 null，角色数不等于 token 成本。
7. 公开经典 Bug 的训练污染无法仅靠禁网排除，可补充较新案例与授权私有案例，但不能声称完全消除污染。

这些是本项目的适配建议，不是外部论文已证明本框架有效。当前封闭裁定接口仍以 `scripts/agent_eval.py` 为准，新分类尚未实现。
