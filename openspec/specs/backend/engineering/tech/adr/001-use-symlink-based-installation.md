# 001：采用软连接安装框架资产

**状态**：Accepted

## 背景

框架原先把 Skill、Agent、Command 和脚本复制到每个目标项目。框架仓库更新后，各项目必须分别重装，容易长期使用旧规则，也无法从框架仓库统一确认安装范围。

## 决策

- 安装脚本仍是唯一安装入口。
- 安装器按 Profile 和 Pack 选择资产，Skill 使用目录软连接，Agent、Command 和脚本使用文件软连接。
- 目标项目使用 Manifest 记录受管链接，用户目录使用 Registry 记录安装目标。
- 已有资产的内容更新沿链接立即生效；新增、删除、重命名资产通过 `--refresh-all` 更新安装拓扑。
- Windows 无法创建软连接时明确失败，不回退为复制。

## 放弃的方案

### 继续复制文件

该方案隔离性好，但每次框架更新都要逐项目同步，无法满足已有内容自动生效的目标。

### 链接整个 `.codex/` 或 `.claude/` 目录

该方案能让新增资产自动出现，但会破坏 Production、Tooling 和 Pack 隔离，也会阻止项目维护自己的 Agent 或 Command，因此不采用。

### 静默回退为复制

该方案会让安装命令表面成功，但后续更新无法自动生效，实际行为与用户预期不一致，因此不采用。

## 后果

- 框架仓库已有内容更新会立即影响所有安装项目，Production 应从稳定分支或稳定 Worktree 安装。
- 从目标项目的受管路径编辑内容，会直接修改框架仓库。
- 框架仓库移动或删除后链接失效，需要从新位置重新安装。
- 新增、删除、重命名顶层资产仍需执行 `--refresh-all`。
- Registry 当前不提供跨进程锁，安装、卸载和刷新命令不能并发执行。

## 适用条件

- 目标环境支持创建软连接。
- 框架仓库保留在稳定路径。
- 项目接受由框架仓库统一提供受管资产内容。
