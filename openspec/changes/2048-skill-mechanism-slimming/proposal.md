# Skill 机制精简

**状态**：Approved

## 1. 背景

基于原始项目的 Skill 已积累兼容路径、运行协议和报告仪式。本次将候选报告中六类裁剪建议及四处规则冲突落实到源码，不再只迁移文案。

## 2. 目标

- 统一普通与轻量交付为 Native Delivery，结束 Fast-Path 独立兼容裁决。
- 保留知识影响检查，无命中只输出简短结论，有命中才展开。
- 复用现有安装能力包，Runtime 和高级知识按需启用；前端与 ocr 保持既有选装。
- 统一 Skill 触发描述和步骤表达，修复四处已知规则冲突。

## 3. 边界与验收

- 不删除质量、安全、批准和证据检查；缺少 Runtime 不得把严格任务降级放行。
- 旧安装不因新默认值静默失去既有能力；已有选择在未显式调整时保留。
- 不增加新插件框架，不删除公共库、外置知识或用户已有文件，不修改全局安装。
- 验证配置保持不变；现有测试基线与新增回归均须核对。
- 原始项目、上轮候选和用户未提交文件保持原样。

## 4. 知识影响

更新安装器、工作流与质量门的长期说明；旧报告保留为历史证据，不覆盖为新版结果。

## 5. 执行授权

用户明确要求「你直接改吧」「不需要我审核了」。本次方案与任务自主落实，不再请求人工方案审核；这不豁免机器验证、独立代码审查或外部副作用确认。
