# 知识管理审查问题修复

**作者**：Codex
**日期**：2026-07-19
**状态**：Archived

## 1. 背景

统一知识管理方案完成后，独立审查提出 1 个 P0、8 个 P1 和若干 P2。复核确认：迁移计划生成器存在 Python 3.12+ 兼容性问题；迁移扫描、公共知识校验器、Fast-Path 交付门、来源新鲜度检查和操作契约存在不同程度的实现或证据缺口。

## 2. 目标

- 修复 Python 3.12+ 下迁移目标计算崩溃。
- 消除迁移引用扫描的已确认重复计算。
- 区分公共知识合同违规与校验器自身错误。
- 让 Fast-Path 的知识影响结论进入机器交付门。
- 对 `meta.yaml` 的 Git 来源新鲜度提供非阻塞告警。
- 校准历史迁移和跨项目隔离的验收表述，并补足可机器验证的边界测试。
- 统一两个脚本的本地 Markdown 链接解析语义。

### 2.1 非目标

- 不实现文件系统 ACL，也不声称项目知识在技术上不可被其他进程读取。
- 不把来源新鲜度告警升级为阻塞门禁。
- 不引入完整 YAML 解析器、RAG 或知识检索运行时。
- 不修改当前文档更新分支 `docs/refresh-framework-features-status`。

## 3. 需求概览

- 所有确认存在的 P0/P1 必须有实现修复或准确的合同校准。
- 接受的 P2 必须有对应测试或明确的操作契约。
- 工具自身错误不得伪装成业务违规或成功。

## 4. 验收标准

- Python 兼容、性能、错误语义、Fast-Path 和来源新鲜度测试通过。
- 历史迁移与项目私有边界的验收描述和证据一致。
- 全量测试、Skill 图和 Workflow Verification 通过。

## 5. 知识影响

- 命中：更新项目知识管理操作契约和历史验收记录。
- 目标：`skills/project-knowledge/SKILL.md`、当前 Change Delta，以及归档后的长期知识管理 Spec。
- 不新增跨项目公共知识候选。
