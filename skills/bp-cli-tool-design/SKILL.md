# CLI 工具设计最佳实践

按任务风险和主题阅读 [reference/cli-tool-design-principles.md](reference/cli-tool-design-principles.md)，不要求常规任务完整通读：

- **所有任务**：阅读「最小设计」「输出、错误与退出码」「交付检查清单」。
- **修改系统或远程状态**：再读「状态变更安全」。
- **处理凭据或日志**：再读「敏感信息与日志」。
- **新增 CLI 或重构入口**：再读「Python 3.8+ 最小模板」和「测试重点」。

## 工作流程

1. 标记工具会读取和改变的资源，识别破坏性动作与敏感数据。
2. 设计参数、前置检查、执行步骤、反馈和退出码；高风险动作先检查再执行。
3. 分离入口编排与核心逻辑，只实现当前需求。
4. 为关键成功路径和失败即停路径补测试。
5. 按参考文档的交付检查清单自检。

## 硬性底线

- 前置检查失败后，不执行状态变更。
- 关键步骤失败后默认停止，并返回非零退出码。
- 主结果走 `stdout`；提示、进度和固定错误摘要走 `stderr`。
- 未知异常对象不得直接输出到终端；详细信息仅写入经过脱敏的日志。
- 密码、令牌、私钥和连接串不得出现在命令行示例、普通输出或日志明文中。
- 目标项目已有更具体规范时，以项目规范为准。
