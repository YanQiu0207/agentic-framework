# 术语表格式

写入或更新 `openspec/specs/business/glossary.md` 时按本文件执行。格式改编自 Matt Pocock `GLOSSARY-FORMAT.md`，资料基准为 `5beb35b040e3de97e54fa9e386d7e42d15c295c2`；落点与授权规则以本框架知识合同为准。

## 条目格式（中文项目）

每个条目一行：

```md
- **{英文规范名}（{中文名}，缩写 {ABBR}）**：{一两句中文定义}。_避免_：{禁用别名}。
```

- 英文规范名与代码中的标识符（变量、类、字段等）保持一致，读代码时能直接对上。
- 中文名必须给出；缩写存在时写进括号，没有就省略「缩写 {ABBR}」段。
- 定义用中文写，一到两句，只说「是什么」，不写「怎么做」。
- `_避免_` 列出禁用的同义词（中英文都算）；没有别名时省略。
- 经用户确认授权写入的条目，在定义后追加来源、确认日期与验证状态；未验证的不得写成已验证。

示例：

```md
## 订购上下文

- **Customer（客户）**：签约购买服务的组织，不是登录用户。_避免_：买家、账户。
- **CustomerAdmin（客户管理员，缩写 CA）**：代表客户管理成员的登录用户。适用范围为订购上下文；来源为用户于 2026-10-25 确认并授权记录，仅澄清既有含义，未作代码验证。
- **Cancel（取消）**：终止整笔尚未履约的订单。

## 财务上下文

- **Customer（客户）**：开票对象，可以是签约组织的结算主体。
```

## 结构规则

- 按业务上下文分节（`## {上下文名}`）；同名概念在不同上下文各有一条，不强行合并。
- 只收项目上下文特有的术语；超时、错误类型、工具模式等通用编程概念即使项目大量使用也不收。
- 同一概念有多个词时选定规范词，其余进 `_避免_`；不写「两个都行」。
- 出现自然聚簇时用小节分组；单一内聚领域平铺列表即可。

## 与上游格式的差异

上游为单上下文仓库在根目录放一份 `GLOSSARY.md`，多上下文仓库用根目录 `GLOSSARY-MAP.md` 做映射，条目为 `**Term**: 英文定义 + _Avoid_`。本框架不建根目录 `GLOSSARY.md` 与 `GLOSSARY-MAP.md`：术语统一写入 `openspec/specs/business/glossary.md`，按业务上下文分节取代 GLOSSARY-MAP，读取经 `openspec/index.md` → `openspec/specs/business/index.md` 定位；中文项目中英文规范名、中文名、缩写与中文定义并列，来源与授权记录是写入前置条件。
