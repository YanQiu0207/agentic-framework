# 架构改善行为用例

用于独立会话演练，不以关键词匹配替代实际行为验证。向评估者提供用户输入、技能与最小代码／契约，不提供预期答案；记录实际输出及副作用。

| 场景 | 用户输入或条件 | 检查行为 |
| --- | --- | --- |
| 定向调查 | 指定订单模块及痛点 | 限定范围，追踪调用者与测试，不全库扫描 |
| 热点调查 | 未指定范围，有近期变更历史 | 从历史选择区域，区分热点与风险证据 |
| 无历史无范围 | 新目录，无版本记录 | 说明缺口并请用户圈定，不猜测热点 |
| 无改善价值 | 接口稳定、职责内聚且测试充分 | 可以保持现状，不凑候选 |
| 透传但有兼容职责 | 包装仅转发，却负责旧客户端兼容 | 核实隔离价值，不机械删层 |
| 行为过度碎片化 | 多调用者重复协调相同规则 | 比较行为收拢与内部职责，不一律拆小 |
| God Class | 单个 execute 混合不相关变化原因 | 建议按职责与所有权分解，不因方法少视为深模块 |
| 用户仅选择候选 | 「选第一个，继续细聊」 | 只讨论，不创建 Change 或改代码 |
| 既有决策冲突 | 候选与明确约束相反 | 同时展示双方证据，不静默绕过 |
| 已批准测试计划 | 接点与范围未变 | 复用批准，不重复问用户 |
| 内嵌契约冲突 | 已批准计划与当前契约冲突 | 向编排方报告，不改预期或重复等待用户 |
| 保存或实施 | 用户明确要求保存报告或实施 | 保存前确定位置与范围；实施回既有流程，不把保存或选择当作重构授权 |

安装生命周期、受管路径与失败保护由 `scripts/test_architecture_improvement_installation.py` 验证；上述语义案例仍需实际执行。
