# 手动回顾：环境扫描

仅 `/reflect` 手动模式读取本清单，自动纠错建议不展开环境审计。

这里的「环境」指 Agent 干活时的「工作台」：它能看到哪些信息、由哪些检查拦截错误、需要承载多少指令，以及能使用哪些工具，不特指操作系统环境。回顾关注工作台如何促成或放过问题，提出导航、检查、指令和工具的改善建议，不直接代替业务代码修复。

## 资料与边界

从当前对话和项目入口定向读取相关指令、目录导航、检查配置及运行证据，不默认遍历全部仓库或会话历史。用户指定或本机可访问且与本次任务直接相关的会话日志可作一手资料；无访问条件时标记「未核验」，不上传原始日志或把敏感内容复制进建议。

扫描只产生建议，不修改配置或规则；验证命令仍遵守项目的执行授权和副作用边界。

## 七类扫描

| 类别 | 检查问题 | 建议方向 |
| --- | --- | --- |
| 导航 | 项目入口能否找到实际模块、命令、知识和规范？是否因路径过时而反复搜索？ | 修复已有导航及读取入口，不复制正文 |
| 自动检查 | 是否缺少可机械判定的护栏？已有 lint、hook、pre-commit 或 CI 是否真执行、覆盖目标并传播失败？ | 新增必要检查，或修复失效接线；存在文件不算通过 |
| 编码标准 | 重复纠错是否揭示未记录的项目约定？既有标准是否可发现、适用？ | 机械部分进检查，判断部分进 Standards，并接现有工程规范审查 |
| 全局指令文件膨胀 | `CLAUDE.md` / `AGENTS.md` 是否堆积非每会话必需的细节、重复或过时规则？ | 依据项目指令文件维护原则提出精简；保留必要导航、批准和停止要求，不自动删除 |
| 工具经济 | 是否重复读取、盲搜、大量无效输出，或反复使用不适合任务的工具？ | 以实际调用证据建议更直接的入口，不凭猜测宣称成本收益 |
| 无效指令（No-ops） | 指令文件中是否存在不改变 Agent 行为的内容？尤其在文件臃肿时，问「删去这条，行为是否会改变？」 | 结合会话证据提出删除或精简候选；不能仅凭一次会话未用到就断定无效，不自动删除，须经用户确认 |
| 信息可及性 | 必需信息是否缺失、难以访问或直到失败才被发现？ | 在已有可信位置补信息或访问指针，不将未核实推测写成事实 |

每类记录「发现及证据」「已核验无发现」或「未核验及原因」，输出可合并无发现项。按项目现有严重度标准排序；未定义时，优先处理会导致错误产物、绕过失败或丢失数据的问题，再处理效率阻力。建议最多三条，但需说明被截断的发现数量；没有有效发现就返回 no-op（无需变更）。这是回顾的退出条件，不是第六类「无效指令」的含义。
