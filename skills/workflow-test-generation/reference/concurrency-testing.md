# 并发测试场景

## 使用边界

涉及多线程、共享可变状态、线程池或并发关闭时加载。先确定线程安全承诺、操作原子性、顺序、取消与关闭语义；未承诺线程安全的接口不擅自新增保证。按实际同步机制选择场景，不要求所有项目引入模型检查工具。

## 场景模板

| 适用条件 | 操作／执行交错 | 预期不变量或完成条件 |
| --- | --- | --- |
| 有共享状态 | 并发读写、读改写、初始化竞争 | 无丢失更新、重复初始化或不符合契约的中间状态 |
| 有任务队列 | 多生产者／消费者，空满边界，重复提交 | 无丢失任务；执行次数与顺序符合契约 |
| 有锁或条件变量 | 反向获取锁、条件变化与等待交错、唤醒竞争 | 无死锁、漏唤醒；操作在约定期限内完成 |
| 有取消或超时 | 取消与完成同时发生，超时后任务继续返回 | 只有合法终态，结果与副作用符合契约，资源正确释放 |
| 有关闭与销毁 | 提交与关闭竞争，等待中关闭，重复关闭 | 新任务按契约接受或拒绝，存量任务按契约完成或取消，无释放后访问 |
| 有线程池或有界队列 | 工作线程全忙、队列满、任务内部提交并等待 | 背压或拒绝可观察，不形成线程池饥饿死锁 |
| 有公平性或无锁进展承诺 | 热点竞争、反复竞争失败 | 满足声明的进展保证；不把普通互斥锁默认视为公平锁 |
| 工作线程可能失败 | 执行中抛出异常或提前退出 | 失败可传播／查询，计数与锁正确恢复，关闭不永久等待 |

## 构造与验证

- 使用屏障、事件、锁闩或可控调度点构造目标交错；不以固定 `sleep` 作为正确性同步手段。
- 为等待与线程结束设置期限，失败时保留线程栈、操作记录与种子；清理本次创建的线程与资源，不遗留后台任务。
- 断言总量守恒、唯一性、合法状态迁移等业务不变量，不只断言「没有抛异常」。只有契约要求线性一致性时，才按该模型检查操作历史。
- 使用语言适用的竞态检测工具，例如 Go 的 `go test -race` 或 C/C++ 的 ThreadSanitizer；记录工具、运行范围与限制，不强制不适用的平台采用它们。
- 在可控交错用例之外，按风险增加重复压力测试；压力测试或竞态检测通过，不证明不存在其他交错下的错误，也不能代替死锁与业务正确性断言。
