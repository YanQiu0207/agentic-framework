# 分布式测试场景

## 使用边界

按项目的通信、数据和恢复契约选择场景。多进程数量不决定测试层级：组件协作属于集成范围，从声明的系统入口到最终业务结果才按系统级 E2E 计划；故障、性能与一致性是可叠加的专项维度。

新系统先明确已确认写入、幂等、消息交付、一致性与恢复期限等承诺。契约不清时按主流程请求确认，不从当前实现或网上案例反推预期行为。无复制、选主或消息队列的系统不强制测试相应机制。

## 场景模板

| 适用条件 | 操作／故障注入 | 预期不变量或完成条件 |
| --- | --- | --- |
| 有远程调用 | 超时、断连、高延迟；服务已提交但响应丢失 | 调用在期限内结束，结果不确定时按契约查询或重试，不重复产生副作用 |
| 有重试与幂等 | 同一请求串行／并发重试；幂等键对应不同载荷 | 相同操作不重复生效；冲突载荷按契约拒绝或处理 |
| 有消息消费 | 重复、乱序、延迟；处理后确认前崩溃；毒消息 | 满足声明的交付与顺序语义，不重复业务副作用，失败消息可处理或隔离 |
| 有跨服务业务流程 | 中间步骤失败、补偿失败、补偿重试 | 状态最终符合业务契约，无悬挂资源；不能恢复时进入明确的人工处理状态 |
| 有持久化和恢复 | 写入过程中崩溃，重启并重新读取 | 已确认数据满足持久性承诺，未完成操作有明确恢复结果 |
| 有复制或一致性承诺 | 副本延迟、网络分区、故障后重连 | 按声明的一致性模型检查读写历史；最终一致性按约定期限收敛 |
| 有选主或租约 | 主节点退出、旧主恢复、租约过期后旧请求到达 | 旧持有者不能执行违约写入；切换期间符合可用性与数据安全承诺 |
| 有动态拓扑或版本演进 | 节点加入退出、滚动升级、混合版本通信 | 路由与协议兼容，无已确认数据丢失或重复业务副作用 |
| 有队列或资源池 | 积压、连接耗尽、下游长期不可用后恢复 | 背压、拒绝与重试受限，恢复后在约定期限内处理积压 |

## 记录与执行

每个选中场景记录：适用条件、测试层级与系统边界、真实／替换依赖、初始数据、注入点、操作步骤、预期不变量、恢复期限、证据与清理方法。

例如「订单提交成功但响应丢失」：在提交后丢弃响应，以同一幂等键重试；断言只生成一笔订单、只扣减一次库存，并在期限内查询到最终状态。此例仅适用于项目已承诺该幂等语义的场景。

- 先用可控替身覆盖错误分支，再用隔离的真实多进程环境验证关键协作；前者不能替代后者的证据。
- 优先显式故障点与同步信号，避免靠随机断连碰运气；随机测试记录种子、操作历史与拓扑。
- 恢复后检查业务数据、消费结果或操作历史，不只检查健康端点变绿。
