# Section 引导指南

本文件用于章节覆盖与内容归位，不规定提问顺序。独立问题可分组，依赖未决答案的问题后置；对话依赖规则统一以主 Skill 加载的 `bp-decision-interview` 为准。只记录用户确认的内容，不能把提前讨论的候选方案写成已批准结论。

## Section 概览

| Section | AI 方案应覆盖 | 此时加载 |
|---------|--------------|------|
| **4.1 方案概览**（最关键） | 模块划分、依赖关系、数据流、与现有代码的关系（新增还是修改）；说明是否有改动范围更小的方案 | |
| **4.2.1 核心类/模块** | 职责划分、模块边界 | |
| **4.2.2 接口设计** | 契约、兼容性、错误码 | |
| **4.2.3 数据模型** | 字段、关系、索引、持久化格式 | |
| **4.2.4 并发模型** | 线程安全、锁粒度、死锁风险 | |
| **4.2.5 错误处理** | 异常分类、恢复策略、降级方案 | |
| **4.3 核心逻辑** | 关键路径、算法复杂度、边界情况 | 完成后加载 `bp-performance-optimization`，从性能角度复核并列出值得做的优化 |
| **4.4 方案优劣** | 优点、局限、风险、改进空间 | |
| **5. 备选方案** | 为什么不选、什么情况下会重新考虑 | |
| **6. 业界调研** | AI 主动搜索相关业界方案，说明与本设计的异同和可借鉴之处 | |
| **7. 测试计划** | 测试类型、覆盖范围、关键用例、边界和异常场景 | `workflow-test-generation` |
| **8. 可观测性 & 运维** | 日志、监控、告警、运维操作 | |

各 section 的方案均由用户确认后写入。用户提出自己的设计时，按同一列检查遗漏和风险。

## 判断 Section 是否适用

4.2.2～4.2.5、7、8 等 section 不涉及时，AI 说明理由并在 design.md 该 section 标注 `N/A - 本需求不适用`，随本轮内容一并请用户确认。
