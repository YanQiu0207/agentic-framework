# Section 引导指南

本文件用于章节覆盖与内容归位，不规定提问顺序。独立问题可分组，依赖未决答案的问题后置；对话依赖规则统一以主 Skill 加载的 `bp-decision-interview` 为准。只记录用户确认的内容，不能把提前讨论的候选方案写成已批准结论。

各 section 的方案均由用户确认后写入。用户提出自己的设计时，按同一列检查遗漏和风险。

## 写作边界

写入 design.md 前逐条自检：

1. **一个主位置**：每条事实或决定只在一个 section 完整写一次，其他位置写「见 design.md §X」，不重述。
2. **关键决定集中写**：每个关键决定在其主 section 写明「选择、理由、放弃方案、代价」；4.4 与第 5 节只做整体评价和整体备选，引用具体决定，不重新解释。
3. **只写本次变化**：现状、既有模型和调研细节引用长期 Specs 或本 Change 的 `research.md`，不整段复制。
4. **抽象层级**：4.1 不写类／接口签名和调用点；签名属于 4.2；4.3 只写关键机制，不默认列完整函数或调用点清单，任务级定位由 `tasks.md` 的 `context_files` 承担。
5. **不适用简记**：只写 `N/A - 本需求不适用` 加一句原因，不写通用教材式解释。
6. **批准后定稿**：设计获批后删除「待审核」「待确认」「推荐」等候选措辞，改为已确认决定，保留取舍理由和必要的历史引用；头部 `状态` 改为 `Approved`。

## 判断 Section 是否适用

4.2.2～4.2.5、6～9 等 section 不涉及时，AI 说明理由并在 design.md 该 section 标注 `N/A - 本需求不适用`，随本轮内容一并请用户确认。常规局部改动没有选型不确定性时，第 6 节按此标注。
